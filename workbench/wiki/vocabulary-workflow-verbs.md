# Workflow verbs: the vocabulary explained

These verbs name the actions every workflow is built from, from the owner's first idea to delivered work and cleanup. Each section says how one verb differs from its neighbours.

The [glossary](../../GLOSSARY.md#workflow-verbs) owns each definition; this article explains how each word differs from its neighbours. It authorizes nothing.

## Align

Grilling supports that inquiry; Confirm closes shared understanding. The execution approval that leaves Prepare grants permission for the stated work; Approve is the later owner review inside Judge.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Workflow

The verb set is open. Reuse an adequate Map or Plan instead of repeating it. Publish is a shared requirement around completed steps, not a repeated diagram box. A failed Review returns to the affected Map, Plan and Journey; a changed concept returns to Align.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Workflow verb

A verb entry defines a meaning; it changes no command, status, folder or gate.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Promote

Decision publication stops there. Preparing a capability through Map and Plan is a separate requested endpoint; neither starts Journey without approval. The core `/promote` skill remains the selected-claim reconciliation primitive.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Record

Recording a proposal does not make it Canon, prove it works or make it complete. `to-docs` routes durable documentation; pending choices keep their pending status.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Publish

A PR preserves progress before publication finishes. PR opening, integration landing and another host fetching or pulling are different events. Publication does not change proposal status, grant authority or prove implementation.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Prepare

Preparation preserves and publishes each result; it does not start Journey without approval.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Ship

“Ship it” grants that permission for the stated work. Confirmation, ordinary approval, Publish and a green check do not. The owner may perform the action or expressly delegate it. Ship it is permission, not a workflow stage; [Deliver](#deliver) acts on it.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Explore

Its result is a confirmed concept, not implicit permission to implement.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Judge

A failed assessment returns to the affected work; a pass does not itself ship to main. Judge is Review, then Verify, then Approve, all before delivery: the review and the owner's approval bind the frozen pre-delivery content, so later delivery bookkeeping keeps them current while a substantive change voids them.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Complete

The runtime completion gate retains its evidence and main-containment requirements. Complete is Deliver, then Cleanup. A Spec names those obligations as `post-delivery` Tasks and `Post-delivery acceptance` lines; `complete` refuses until they are done with proof.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Jot

The `jot` skill carries capture and focused retrieval; new project context is shared by default and published through the authorized workflow; explicit private capture stays ignored. Confirmation, scoped approval and implementation proof remain distinct.

For missing local continuation context, the `jot` skill uses bounded topic
search; private retrieval is an explicit local opt-in within unchanged access.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Idea

Not Fog: Fog is anticipated work toward a destination that cannot yet be stated as a precise decision question.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Confirm

Confirmed is Human Verified Intent. The owner may confirm and approve together, but they remain distinct judgments. A readback or Confirm button establishes only the understanding it names; an agent's recommendation remains a proposal until confirmed.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Prototype

It comes before Confirm or between Confirm and Plan. The `prototype` skill carries the method.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Plan

One Task is enough when it covers the outcome. Preparing Tasks does not activate implementation; approval is required to start Journey.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Implement

The first verb of the Journey. What it writes, Canon or Actuality, is in the Writer verb entry.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Check

Checks are deterministic verifications that run in the environment. It is an Automated check, with no judgement in it; QA follows. Worker self-check names Check and QA together from the Worker's side.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## QA

QA is a self-judgement check on the work. It comes after Check and before Submit. It is not Human QA, the owner's evaluation of delivered work, and not a Review, which is another agent's judgement.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Submit

The last verb of the Journey for that Task. The Spec's Dispatcher, Director or next agent validates the answers and merges when the merge is green; a Task gets no Review ([the rule](../docs/SKILLS.md)).

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Review

An Automated review. Not Human review. Independent review of an assembled Spec at its Verify step is required by `AGENTS.md` [Git Rules](../../AGENTS.md#pr-instructions); the [`code-review` skill](../docs/SKILLS.md) prepares, records and checks it; this entry says what counts as one.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Verify

A failed Review goes back to Map, Plan and Journey before the work can be verified. `AGENTS.md`'s closure sequence also has a verification on main, after owner approval; this entry gives the verb's own meaning and changes neither.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Journey

Journey is the build run for each planned Task; Map and Plan stay outside it, and a failed Review sends the work back to Map, Plan and Journey. It is the loop-level name, not a stage a card can sit at.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Approve

Approved is Human Reviewed Work: the owner's judgment after Review and Verify, recorded with the `approve` command against integration content. It does not authorize main; Ship it does. It is not the execution approval that leaves Prepare, which may accompany confirmation and need not be requested again for already authorized work.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Deliver

Deliver acts on Ship it for the specific approved candidate, then verifies the delivered content against the approval; for the main-delivery workflow the approved content must be unchanged on main. It is the first step of Complete.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Delivered

Integration publication is an earlier boundary. The existing `complete` command and `S-###:delivered` dependency qualifier retain their distinct runtime meanings; neither silently grants main authority.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).

## Clean Up

Cleanup is the step of Complete that performs it, after Deliver. Scaffolding names what is cleared; the Retired entry is the staging place, and `retire-spec` and `discard` carry it out for Specs and Tasks.

Definition: [GLOSSARY.md, Workflow verbs](../../GLOSSARY.md#workflow-verbs).
