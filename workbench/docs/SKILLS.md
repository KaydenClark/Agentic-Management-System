# Workbench skills

The shared personal catalog owns the methods; project skills are extensions.
Read the installed personal skill and its reached references before the operation.
The manifest and this project's controls bind paths, authority and delivery.

## Changes to the shared catalog

A shared-skill change is still AMS work even when its source is in another
repository. Recover intent and current records, use map for the destination
and plan for bounded Tasks, and reconcile affected Wiki/docs before source
implementation. Respect the requested phase: Prepare-only work leaves a
planned, unclaimed destination and grants no activation or trial authority.
Author reusable source in KaydenClark/skills through author-skill; this
project's skill lane is not its replacement. See the [catalog refocus](../landmarks/LMK-004-rsi-loop-during-build/specs/S-000A-skills-refocus/SPEC.md)
and [preparation-bypass failure](../feedback/REPORT-skills-workbench-bypass-2026-11-02.md).
This routing clarification is not proof that the systemic failure is fixed.

## Runtime

From the project root, inspect with
`node workbench/tools/spec-workbench.mjs doctor`, `next --json` and `show SPEC_ID`.
Use the actual claim/receipt/close interface under current authority; never edit
around a refusal. Regenerate TASKBOARD with `render`. It projects Spec/Task truth.
Tool receipts guard managed bytes. Edit `workbench/tools/` only via setup-workbench; author skills via author-skill. Explicit updates and backups belong to setup.

## Ownership

Legacy method names in historical reference text describe earlier generations.
Use the operation map above and the current personal skill, retaining the named
runtime operation and its gates. Missing capabilities or an unavailable host
invocation remain setup gaps. A path check is not host activation.

## Delivery

The project controls own branch targets, required review, Human QA and publication.
Read back owners, diff, candidate, target, checks and limits; report push, merge and deployment separately. Record only eligible Review and actual Human QA. An implementor's QA is not independent review. Setup, a successful check, a pushed
branch or a PR never grants permission to merge main or deploy.

The [owner's standing publication authorization](../wiki/context-grilling-board.md#jot-d24d46bd-7ca5-44e0-854e-0411e4fbff30) covers routine public project records; preserve its exclusions, confirmation states and website promotion gate.

## RSI operations

Record issue, baseline, hypothesis, before/after, failures and disposition; show the scoped log on the website. Repair shared skills in `KaydenClark/skills` through author-skill. Install into the personal catalog only with authorization. Do not roll out to other projects. Static scores alone prove no behavioral benefit.
